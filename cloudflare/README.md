# jrxy_auto_cf · Cloudflare 部署与升级

**签到 / 查寝、每日定时、多账号暂停、通知与日志。** 采用 Workers + D1 + Queues，原生 HTML/CSS/JS 管理台，桌面与手机自适应。不需要自己的服务器、Docker、付费容器、R2 或 OCR。

现有 GitHub → Cloudflare 自动构建流程继续使用：**GitHub 保存代码，Cloudflare 运行同一套网页和后端**；不是另做 GitHub Pages，也不需要新增 GitHub Actions。

> 本地 workerd、模拟学校/通知和浏览器交互已验证；没有替用户部署公网、使用真实学校账号签到或发送真实推送。远程免费CPU/额度、学校网络和协议兼容性需部署后实际核实。

## 1. 从旧版升级：先看这里

1. **保留原 D1 数据库、队列名称、绑定和 ENCRYPTION_KEY**，不要重建数据库或生成新的数据加密密钥。`jrxy_auto_cf` 是项目名，新安装的Worker默认使用 `jrxy-auto-cf`。已有部署升级时，请把 `wrangler.jsonc` 的 `name`、数据库ID和队列名保持为你现有资源；不要仅因项目更名新建一个同时执行Cron的Worker。
2. 在 Cloudflare Worker 的“设置 → 变量和机密”新增两个 Secret：
   - `ADMIN_USERNAME`：独立管理员账号，例如你自己设置的管理用户名。
   - `ADMIN_PASSWORD`：至少12字符的随机强密码，推荐20字符以上。
3. 旧 `WEB_TOKEN` 不再参与鉴权，可以删除。它不能绕过新的账号密码登录。
4. 项目 `cloudflare/` 的 `npm run deploy` 会先检查，再执行D1增量迁移，成功后部署Worker；新迁移只增加暂停/会话等字段和表，不删账号、deviceId、计划或日志。
5. 更新后管理员进入 `/admin`，使用管理员账号密码；默认 `/` 为用户授权码授权页。
6. 新增迁移 `0005_redemption_grants.sql`，增加授权码、短期验证任务、账号授权期限和身份摘要。已有手动账号不设置到期时间、不被自动删除。
7. 本次新增 `0007_authorization_code_copy.sql`（新码可恢复密文）和 `0008_execution_priority.sql`（权重、分组、并发设置和执行位）；旧账号/期限不变，旧任务继续串行，新并发默认1。不要为了升级更换ENCRYPTION_KEY。
8. 本次新增 `0009_retry_evidence.sql`：保存目标任务、账号未决提交、串行降级原因和队列投递标识；只迁移最新尚未解决的旧提交，不复活已解决记录、不改旧重试预算。新定时批次默认首次＋5次额外重试；后台显示实际参数。迁移先于Worker发布，沿用原ENCRYPTION_KEY。
9. 新增 `0010_execution_diagnostics.sql`，仅为历史日志增加可空诊断字段；不修改旧日志、账号或任务结果。版本元数据绑定无需新增Secret，升级仍沿用原ENCRYPTION_KEY。
10. 首次成功授权默认启用尚未由管理员设置的每日计划（默认北京时间22:05），账号自动加入后续计划。管理员已保存过的开关与时间保持不变；如果主动关闭过全局计划，兑换不会强制重启。分发授权码前请核对计划时间及所有正常账号的配置。

**密码及 ENCRYPTION_KEY 不上传 GitHub。管理员凭据变更会使旧管理会话失效，但不会更换校园账号密码或设备ID。**

## 2. GitHub 连接 Cloudflare 自动部署（推荐，沿用现有方式）

Cloudflare 控制台中连接现有 GitHub 仓库/生产分支，配置：

| 配置 | 值 |
|---|---|
| 根目录 / Root directory | `cloudflare` |
| Node.js | 22 或更高版本 |
| 安装依赖 | `npm ci`（平台自动安装时使用锁文件） |
| 构建命令 / Build command | `npm run check && npm test && npm run build` |
| 生产部署命令 / Deploy command | 使用下方数据库ID注入命令，最后运行 `npm run deploy` |

`npm run build` 只进行 Wrangler dry-run，不修改生产库；`npm run deploy` 才执行 `wrangler d1 migrations apply DB --remote` 后发布。

### 构建环境注入数据库ID

仓库的数据库ID保留全零占位。在Cloudflare **构建环境**添加 `D1_DATABASE_ID`，值为你创建的D1数据库UUID；生产部署命令填写：

```bash
node -e "const fs=require('node:fs');const id=(process.env.D1_DATABASE_ID||'').trim();if(!/^[0-9a-f]{8}-([0-9a-f]{4}-){3}[0-9a-f]{12}$/i.test(id))throw new Error('Invalid D1_DATABASE_ID');const p='wrangler.jsonc';const c=JSON.parse(fs.readFileSync(p,'utf8'));c.d1_databases[0].database_id=id;fs.writeFileSync(p,JSON.stringify(c,null,2));" && npm run deploy
```

只修改构建环境中的临时配置，不提交真实ID。已有部署使用同一命令无需更换；首次发布未设运行时Secret时接口会安全拒绝运行，发布后补齐三个Secret即可。

### 两类机密不要混淆

- **运行时 Secrets**：`ADMIN_USERNAME`、`ADMIN_PASSWORD`、`ENCRYPTION_KEY`，放在 Worker 运行时配置。不要放在静态网页、仓库或日志中。
- **构建部署凭据**：Cloudflare Git 集成使用的 API Token / Account ID。如果迁移提示权限不足，部署令牌除Workers脚本权限外，还需目标账号D1编辑权限及该配置所需的Queues权限。按实际资源最小授权，不授予无关账号权限。
- 构建环境变量不会自动成为运行时Secret，运行时Secret也不应为测试而复制进GitHub。

只有生产分支使用以上生产部署命令。部署脚本会拒绝全零数据库ID；Workers Builds 提供的 `WORKERS_CI_BRANCH`（兼容 `CF_BUILD_BRANCH` / `CF_PAGES_BRANCH`），还会核对 `PRODUCTION_BRANCH`（默认 `main`）。若你的生产分支是 `master` 或其他名称，请在构建环境设置 `PRODUCTION_BRANCH`。**非生产分支建议只执行检查和dry-run，关闭自动非生产发布**；不要让预览部署复用生产D1、队列或Cron。需要在线预览时，必须另配测试Worker/D1/Queue且关闭定时。

本地手动部署也执行同一个 `npm run deploy`，因此两种方式没有另一套签到或通知逻辑。

## 3. 首次部署

在 `cloudflare/` 中执行：

```bash
npm ci
npx wrangler login
npx wrangler d1 create jrxy-auto-cf
npx wrangler queues create jrxy-auto-cf-jobs
```

仅在本地部署时，将D1返回的 `database_id` 写入本地 `wrangler.jsonc`，不要提交该真实ID；Git集成按上一节使用构建环境注入。Worker名、数据库名和队列名如需调整，请同步修改相关配置。

设置运行时Secret（如果Worker尚不存在，可先发布一次；缺少Secret时API与任务安全拒绝运行）：

```bash
npx wrangler secret put ADMIN_USERNAME
npx wrangler secret put ADMIN_PASSWORD
npx wrangler secret put ENCRYPTION_KEY
npm run deploy
```

新安装的 `ENCRYPTION_KEY` 使用32随机字节的标准Base64，可生成：

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
```

此命令仅用于首次安装。**升级必须沿用原密钥并做好备份，丢失密钥会无法解密旧账号。** 测试中的全零密钥与示例密码禁止用于生产。

安装后尚无授权时默认关闭；首次成功授权可自动启用未由管理员设置过的每日计划。部署完成后 `https://...workers.dev/` 是用户授权页，`https://...workers.dev/admin` 是管理员登录页。

## 4. 管理台登录与安全

- 一个独立管理员账号，无公开注册和弱密码默认值。
- 生产会话Cookie：`__Host-` 前缀、HttpOnly、Secure、SameSite=Strict，12小时过期；D1只保存随机会话ID摘要。
- 浏览器不保存管理密码或访问令牌到 localStorage；CSRF值只在页面内存中。
- 写入API校验同源与CSRF。退出会使当前会话立即失效，凭据轮换会使所有旧会话失效。
- 登录请求按IP及全局限频；测试推送每账号每分钟最多一次。
- 管理员密码保存在受控Cloudflare Secret，D1不保存它；不要在任何日志中打印请求体。
- 密码忘记时，通过有权限的Cloudflare控制台重新设置 `ADMIN_PASSWORD`，不提供不安全的邮箱找回入口。
- 本机 HTTP 使用独立的开发Cookie；远程登录必须HTTPS。

## 用户授权与授权码

默认首页让用户填写**授权码、姓名、学校账号、学校密码**。姓名限制1～50字符，加密保存并作为后台账号的显示名称；内部账号ID保持稳定，同名不同账号不冲突。管理员可以编辑显示名称，旧账号没有姓名时继续显示原账号名。用户不填写学校、签到类型、经纬度或地址；可自行选择是否启用Server酱通知，默认关闭。

### 管理员生成

在 `/admin` 的“授权码管理”创建批次：数量为整数 **1～10**；预设学校、签到/查寝形式、GCJ-02经纬度和地址；使用时长默认24小时，可按整数小时或天调整，最长365天；可单独设置最晚使用时间。升级不会缩短旧批次或已开通账号的期限。

- 每码128位随机强度，一次只绑定一个账号。
- 生成后显示准确数量和**一行一个码**的文本，支持复制全部或逐行复制。
- 新码保存带密钥摘要和AES-GCM密文，未使用且未过最晚时间时可再次复制；复制需管理员会话、CSRF与限速，支持单码和整批一行一个，响应不缓存。旧摘要码无法还原，仍可按原规则使用。
- 列表每页10条，可翻页管理历史码，不会自动让旧码失效。跨页批次操作覆盖整批，页面标出本页/整批数量。
- 整批撤销包括验证中但尚未成功激活的码，事务清除临时个人信息；已使用码和已开通账号不受影响。使用/撤销清除码密文，过期密文由Cron分批清理，已用摘要不复活。
- 学校、坐标、类型等批次预设固定；通知只接受单独开关和合法SCT SendKey，用户不能通过其他字段覆盖学校预设或提升权重。
- 最晚使用时间限制“何时可以授权”；使用时长从“登录验证成功并完成账号创建”的时刻起算，两者独立。

### 验证与开通

保存时先占用授权码，按原项目规则沿用或生成deviceId并保存到短期待验证记录，再执行学校登录验证，最后用一个数据库事务完成绑定和创建账号。成功之前只显示验证/设置状态，不先弹保存成功；登录失败会清除临时姓名、密码和设备标识。

- 登录失败、验证码、网络异常或验证超时，不创建启用账号、不消耗码，清除临时凭据；受限次数后需等待再试。
- 同一码同时兑换、重复点击、队列重复投递只允许一次绑定。
- 当前已有同学校同账号不会被覆盖，需管理员核对。
- 通知默认关闭；用户可打开“Server酱通知”开关并填写SCT SendKey，不接受任意Webhook。开关与Key随账号加密保存，授权/登录验证不发送测试消息，失败或到期清理Key。后台显示相同配置并可修改。
- 开启时弹窗提示前往 [Server酱登录](https://sct.ftqq.com/login)，按官方页面微信扫码、关注并配置通道，复制SendKey后返回本站。新标签外链不携带个人参数，不读取微信登录状态；消息额度与送达以第三方规则为准。
- 兑换成功默认启用该账号并加入每日自动签到；初始全局计划自动开启，默认北京时间22:05，管理员保存过的开关和时间不覆盖。兑换本身不立即签到、不补跑开通前的时间点，只参与后续计划。
- 默认验证回执有效10分钟；不要把验证页刷新或关闭后当成未提交，响应不明时先核实结果，不能盲目重复兑换。

### 设备标识：按原版方式

自助兑换用户不填写deviceId。系统优先沿用本系统能够确定属于同一学校/账号的原绑定；没有时生成一次UUID并持久化，后续不变。这是原Python首次生成并固定的规则，**不是从手机读取真实ID**。学校如果要求已有设备授权，新生成值可能被拒绝，需要管理员人工处理，不能因为登录通过就承诺真实签到必定成功。

后台手动创建账号同样默认自动处理deviceId；迁移时可选填原ID。编辑留空保持已保存值，已有绑定不变，执行与重试期间不会临时生成替代ID。原Web探测先调用 `ensure_device_id()` 再启动脚本；原单独登录测试只验证CAS/IAP，设备ID参与后续动态密钥协商和签到，不能把登录通过当成设备授权通过。

### 开通失败诊断

后台“最近开通验证”显示近期最多50条状态，可手动刷新，记录约10分钟后随短期任务清理。`0006_enrollment_diagnostics.sql` 仅增加可空诊断字段及索引，不修改旧账号/计划。

- 区分获取学校列表、学校详情、校园入口、登录页、票据、验证码检查、登录提交和回跳阶段。
- 只记录目标域名、方法、HTTP状态、错误分类和有界计时数据（请求序号、跳转次数、请求及会话耗时、等待阈值、距上次进展时间、已读字节数）；不记录完整URL/参数、正文、原始异常、Cookie、姓名、密码或SendKey。
- 区分等待首次响应超时、正文无进展超时、会话网络总时限；另保留传输、正文中断、响应处理和HTTP异常分类。诊断中的首次响应等待包括fetch返回响应头之前的各段耗时，不表示已经测得TCP连接时间。
- 收到响应头后重新开始正文等待；收到非空分块即刷新该等待阈值，慢而持续的流不会因为下载总时长超过单次阈值被中断。会话网络总时限、响应大小和跳转次数限制不变，不添加自动重放登录或签到POST的机制。
- 已修复原生fetch被当作Session对象方法调用导致的 `Illegal invocation`：该错误发生在请求发出前，旧版却归为连接失败。现在使用普通函数调用，明确的调用异常归为internal而非DNS/TLS，不自动重试。
- 其他transport失败仍无法仅凭Workers通用异常判断是DNS、TLS还是连接中断。将后台同次失败记录的阶段、域名、方法、HTTP状态和耗时用于排查；不要发送账号、密码、Cookie或完整授权码。
- 原Python部分请求关闭证书校验，Workers fetch不会照搬；国内或境外服务器正常不等于Cloudflare出口一定正常。需要依据实际失败阶段核实，不关闭TLS校验、不加入不可信代理或自动连续登录。
- 诊断接口仅管理员可访问；用户只看到安全的错误分类及未开通/未消耗码提示。旧版本已失败的记录不能补出当时未采集的信息。

### 执行日志与反馈

签到、探测、登录测试、范围获取结束后，在结果区域展开“第N次逐请求诊断”；历史每一轮可在“运行日志”展开查看。点击“复制脱敏诊断”，把生成的JSON反馈即可，不必复制带账号名称的整块页面。批量最多复制10条，超出会提示省略数量；剪贴板权限不足时显示可选中文本。

诊断包含随机编号、Worker版本UUID（平台提供时）、UTC时间、模式/轮次/并发/实际超时预算，以及每个请求的固定阶段、方法、域名、响应头等待/正文耗时/累计耗时、HTTP状态和白名单错误码。若有合法上游Ray ID一并保留。不包含姓名、学号、密码、deviceId、位置、Cookie、票据、授权码、通知Key、URL参数或响应正文。

“未取得响应头”不能区分DNS、TLS、连接或上游处理，也不能证明请求没有送达；“请求完成”只表示响应读完，不代表签到成功。详细日志用于定位，不自动修复网络。每次最多41条/32KiB，在报告事务保存，不为每请求新增D1写入；只有执行结束后可查看，不是实时抓包。平台直接终止、旧版本历史记录可能没有轨迹，不会伪造补齐。

完整诊断不自动附加到外部通知；只有管理员点击复制时进入剪贴板。日志清空会删除历史诊断，授权账号到期清理也会删除其诊断及任务结果。

### 到期与个人数据清理

到期立即在建任务、队列消费、重试与提交前阻止新签到；每分钟Cron分批清理账户密文、deviceId、短期凭据、相关任务和含个人信息的日志/汇总。账号删除不让已使用码复活。

- 清理只影响兑换账号，手动创建账号没有默认到期时间。
- 已用码保留摘要、批次、使用时间和截止时间等最少审计字段，不保留学号密码或设备ID。
- 验证失败的临时记录清除凭据后短期保留结果，约10分钟后清理；过期验证不自动反复尝试登录。
- 到期前已发出的网络请求无法撤回。清理会删除在线业务记录，但Cloudflare数据库备份/Time Travel保留期由平台控制，不承诺物理备份立即擦除。
- 公共接口仅开放明确的兑换路由，并校验HTTPS/同源、随机回执和频率；管理API仍需管理员会话。

## 5. 账号暂停与恢复

账号列表可暂停/恢复，状态持久化在D1，不因部署更新丢失：

- 暂停期间，定时/批量/单账号手动**签到提交都禁止**。
- 编辑、登录测试、只探测、范围查询和通知测试仍可用。
- 排队但尚未提交的签到/重试会被取消，日志记为暂停跳过，不发多余“签到失败”通知。
- 提交前再次核对暂停状态和版本；暂停后立即恢复也不会让旧队列消息重新执行。
- 恢复不补跑暂停期间的时间点，只接收新手动任务和后续定时。
- 已发出的请求无法撤回；如果操作发生在提交开始之后，页面提示可能已进入提交阶段，最终结果和通知照常记录。
- 暂停不清除学校密码、设备ID、位置或推送配置。

## 6. 签到、查寝与通知

使用现有 `src/engine/` 主链路：固定设备标识 → CAS/IAP登录 → 查询任务 → 表单校验 → 动态密钥 → `ios + first_v4 + fkey_cat` 提交。

请求顺序区分原入口：登录测试/授权开通与范围获取走一次学校发现；探测/签到保留原脚本的两次学校发现和登录后再次租户查询。CAS会重新GET登录页，IAP的票据/验证码`{}`正文不额外添加Content-Type；不再用学校元数据缓存跳过请求。详情见[流程对照报告](../docs/FLOW_REVIEW.md#请求轨迹复核)。

- 类型只包含 `1 签到` 和 `2 查寝`，不做照片上传/收集/政工/教师日志。
- 两个入口均在登录前按原规则沿用或首次生成并保存固定 `deviceId`；后台手动填写旧ID为可选。两种入口均不能仅凭ID字符串证明手机已获得学校授权。
- 学校密码编辑留空保持原值；密码永不回显。
- 探测只登录、查询和构造请求，不提交签到。
- 原 `forms/formTitle/checkTitle` 规则继续支持，可通过旧配置迁移/API维护；编辑普通字段不会删除它们。
- 获取签到范围仍会应用到位置配置；请确保提交的位置与实际情况及学校规则一致。

### 通知落实方式

沿用原Web的Server酱/Webhook功能：

- `SCT...`（Turbo）、`sctp...`（Server酱³）、完整HTTP(S) Webhook地址。
- 原 `title/desp` 表单格式、状态标题、账号名、触发来源、开始/结束时间及脱敏详情。
- 手动/批量/定时签到推送；探测默认不推送，`NOTIFY_ON_DRY=1` 开启。
- 定时重试的中间异常不推送，最终结果才推送。
- 账号编辑的“测试推送”使用**已保存配置**，明确发送测试消息，不登录学校、不签到；真实点击将对外发送消息。
- HTTP/服务返回成功只代表“服务已受理”，不保证手机已收到；额度不足、地址错误等写入日志。
- 发送过程中进程中断可能无法确认送达，记录未知，不冒充成功或无限重发。

## 7. 每日定时、优先级与并发

### 权重与执行设置

- 账号权重为0～100整数，默认0、越大越优先。编辑账号或多选批量设置，用户授权入口无权自行提升。
- 定时/批量创建时保存权重和顺序快照；修改权重只影响新建批次，不抢占在途请求。
- 后台“执行设置”独立选择1、2、3并发，默认1，不改变每日计划开关。Cloudflare消费者上限3、每次一条账号消息，实际准入由D1执行位和账号锁限制。
- 同权重分组，每组最多按建批时的上限执行；本组尝试与报告完成后，等待原间隔再进下一组。高权重组先执行，同组完成顺序不保证。并发上限降低时停止额外准入，已有任务自然结束；提高后后续批次采用更大组，已有组不重排。
- 授权登录验证共享容量，无空位时等待，不反复尝试密码；原10分钟回执期限仍生效。已在等待的队列消息会有持久化预留，发送失败/租约过期可恢复。
- 升级前任务默认按原序列串行；旧全局门闩仍被兼容检查，不在滚动升级时绕过旧任务。
- 建议先观察2并发再决定3。多并发不增加免费额度，也不会降低每条Queue消息的操作数；CPU超限、积压、D1用量或学校418/429需人工降低并发/暂停检查，不保证任意账号规模都免费稳定。

### 计划参数

| 变量 | 默认 | 用途 |
|---|---:|---|
| `AUTO_SIGN` | `0` | 首次初始化开关，之后页面/D1设置优先 |
| `SIGN_TIME` | `22:05` | 首次每日时间 |
| `TZ_OFFSET` | `8` | 业务时间/日志时区 |
| `CATCHUP_MINUTES` | `120` | 延迟触发后的补执行窗口（暂停账号不补） |
| `JRXY_INTERVAL` | `10` | 同批次账号完成后的间隔秒数 |
| `JRXY_HTTP_TIMEOUT` | `60` | 普通学校请求等待首次响应头及正文无进展阈值（秒）；动态密钥协商与签到提交仍显式20秒 |
| `JRXY_RUN_TIMEOUT` | `300` | 单账号网络总时限秒数 |
| `RETRY_DELAY_MINUTES` | `5` | 整轮完成后再等候重试 |
| `MAX_RETRIES` | `5` | 定时最大额外重试次数，首次＋5次共最多6轮；旧在途批次保留原预算 |
| `NOTIFY_ON_DRY` | `0` | 探测通知开关 |

Cron每分钟检查，Queue按账号分发；默认一次一个账号，可在执行设置选择2或3并发。D1执行位、账号互斥和任务版本处理重复/乱序/恢复。退出管理台不会停止定时。

普通请求默认等待从原30秒提高为60秒，用于容纳30～60秒的慢响应，不是保证可达性的修复。管理员“执行设置”显示实际网络参数；显式环境配置优先，以页面和新诊断的 `timeoutMs` 为准。总时限仍300秒、提交和密钥20秒、通知15秒。已开始的执行保持启动时预算，下一执行读取新参数；已耗尽预算的任务不会因升级自动复活。

修改或关闭全局计划不打断已经开始的批次；**暂停单账号**则会取消它尚未提交的旧任务。所有账号完成本轮及报告后才计时等待下一轮，成功/明确失败/验证码/暂停不盲重试；手动与普通批量仍是单次。

提交超时先复查同一任务，已签才算成功、明确未签才允许后续重提；查不到原目标或复查失败时保留检查点进入有限复查，不再直接放弃，也不盲重签。六轮耗尽仍记待确认；后续手动/定时继承未决检查点。旧目标跨日不再出现在当日列表时需要人工核实。

单账号手动点击和“签到全部”都会接续已有签到/重试任务，空闲账号才新建；同一未结束批次的成功账号只展示结果。后台显示新增/接续/已成功数量，暂停、其他操作占用和到期失效分别提示，不将待重试统一当作无可执行账号。接续不会重置次数或提前跳过整轮等待。后台显示轮次、剩余机会、下一次最早时间与仅复查状态。可信空列表显示无待签任务，不是签到成功；缺字段/业务异常不能伪装成空列表。“已结束”只表示执行结束。

门户阶段HTTP 520等5xx表示收到上游服务错误，并不表示已提交签到，也不能仅凭该日志判断由更新引起。5分钟重试等待从所有账号本轮执行和报告结束时起算，不从第一个失败账号报错时起算。

并发批次出现明确上游网络暂时错误，下一重试轮降为串行，记录原因但不改变全局并发上限。正常并发保留；418/429立即停止自动请求。升级后应核对实际MAX_RETRIES，环境显式覆盖优先。连续进程中断仍有独立保护上限，不以无限重启替代业务重试。

Cron/Queue不是硬实时，实际开始可能晚于设定时间，首次Cron配置传播可能需要数分钟。不要同时在旧服务器和新Worker对同一账号开启自动签到。

## 8. 免费计划与外部边界

配置不使用付费容器、R2、AI、OCR或额外计算服务器。仍要遵守账号共享额度：

- Workers Free：每日100,000请求，HTTP/Cron CPU预算小（文档10ms，网络等待不计CPU）。
- Queues Free：每日10,000操作；小消息通常写/读/删共3次，重试另计，保留24小时。
- D1 Free：每日500万行读、10万行写；单库500MB、账号总存储5GB。
- 每分钟Cron约每日1,440触发，空闲时不持续发队列消息。日志不自动删除，请按需清理。

本地测试不等同远程CPU配额验证。首次上线检查 Workers Metrics 中 `exceededCpu`、Queue积压与D1用量，不能承诺任意学校/账号数都免费稳定。

学校须公网HTTPS可达且证书有效。校园内网、原 `requests` 本地代理、关闭证书验证或特殊MFA不能在本版本中原样使用；HTTP代理配置为迁移保留，非空会明确拒绝而非静默直连。

**不使用OCR**；登录临时要求验证码时停止并记录/按签到通知配置报告。原PythonCLI未作为Web入口的Android/App实验分支、APPRISE插件不是本版的新入口。

## 9. 旧账号迁移

保留原 `.device_id`。默认只检查、不联网、不导出密码：

```bash
python -I cloudflare/scripts/import-accounts.py --accounts /path/to/accounts
```

确认要上传至自己的部署后，设置环境变量 `JRXY_ADMIN_USERNAME` 和 `JRXY_ADMIN_PASSWORD`（不是学校账号），执行：

```bash
python -I cloudflare/scripts/import-accounts.py --accounts /path/to/accounts --url https://YOUR-DEPLOYMENT --apply
```

工具先管理员登录，通过会话/CSRF导入，结束后退出；不覆盖已有账号、不自动学校登录/签到/推送。不再使用 `JRXY_WEB_TOKEN`。

原 `jrxy-engine/scripts/extract_deviceid.py` 或鉴权后的 `/api/device-id/extract` 仍可提取本人提供的原协议头，不新增手机扫描/自动获取能力。
